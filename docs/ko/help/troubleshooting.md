# 문제 해결

먼저 증상 표를 확인한 다음, 아래의 포트 참조와 해당 증상에 맞는 점검 항목을 사용하세요. macOS, Windows, 공급자의 보안 제어 기능을 활성화된 상태로 유지하고, 해결 방법으로 방화벽, SmartScreen 또는 기타 보호 기능을 전역에서 비활성화하지 마세요.

## 빠른 해결 경로

| 증상 | 가장 빠른 확인 방법 | 해결 방법 |
| --- | --- | --- |
| macOS에서 “손상됨” 또는 “열 수 없음”이라고 표시됩니다 | 서명되지 않은 프리뷰 빌드인지, Atoll이 의도한 릴리스에서 제공된 것인지 확인합니다 | [macOS 설치 단계](/ko/getting-started/install-macos)를 따릅니다. Gatekeeper를 전역에서 비활성화하지 마세요. |
| Windows에서 SmartScreen 또는 Smart App Control이 표시됩니다 | 설치 프로그램이 의도한 Atoll 릴리스에서 제공된 것인지 확인합니다 | [Windows 설치 단계](/ko/getting-started/install-windows)를 따르고 문서에 설명된 앱별 신뢰 절차를 사용합니다. SmartScreen 또는 Smart App Control을 전역에서 끄지 마세요. |
| 공급자 연결 시 브라우저가 열리지 않거나 콜백이 실패합니다 | `17872`가 이미 수신 대기 중인지 확인합니다 | `lsof -i :17872`를 실행하고 다른 공급자 로그인을 완료한 다음 다시 시도합니다. 콜백은 `127.0.0.1:17872`에 바인딩됩니다. 현재 구현에서 Windows 공급자 OAuth는 검증되지 않았습니다. |
| Magnific에서 “premium required”라고 보고합니다 | 브라우저에서 Magnific 계정의 플랜을 확인합니다 | Magnific MCP 액세스는 Premium 플랜으로 제한됩니다. 적격 플랜으로 업그레이드하거나 전환하고, 권한 변경이 전파될 때까지 기다린 다음 공급자를 다시 연결하거나 새로 고칩니다. |
| `$` 견적이 표시되지 않습니다 | 노드가 사용하는 공급자/모델을 확인합니다 | `$` 배지는 자동으로 보장되는 값이 아니라 필요할 때 조회하는 실행 전 견적입니다. Kling에는 실행 전 견적 도구가 없으므로 견적이 표시되지 않는 것이 정상입니다. 실행하기 전에 공급자의 가격과 잔액을 확인하세요. |
| 30분 후 작업 시간이 초과되거나 재시작 후 결과가 누락됩니다 | 해당 워크스페이스 탭을 열고 작업 조정이 완료될 때까지 기다립니다 | Atoll은 30분 후 로컬 폴링을 중지합니다. 워크스페이스를 다시 열어 저장된 작업과 완료된 결과를 동기화하세요. 추적 시간 초과가 공급자 작업을 취소하지는 않습니다. |
| 에이전트 터미널에서 `claude` 또는 `codex`를 찾을 수 없다고 표시됩니다 | 로그인 셸에서 `command -v claude` 또는 `command -v codex`를 실행합니다 | CLI를 설치하고 로그인한 다음, 해당 디렉터리가 로그인 셸의 PATH에 있는지 확인하고 Atoll 터미널 세션을 다시 시작합니다. |
| 에이전트에 MCP 도구가 표시되지 않습니다 | 포트 `17873`을 확인하고 세션을 다시 시작합니다 | `lsof -i :17873`을 실행해 Atoll 로컬 MCP 서버가 수신 대기 중인지 확인한 다음, 에이전트 세션을 종료하고 다시 시작해 워크스페이스 `.mcp.json` 또는 Codex 세션별 재정의를 다시 불러옵니다. 워크스페이스 탭을 열어 두세요. |

## 공급자 연결 및 콜백

Atoll은 공급자 로그인 URL을 열기 전에 `127.0.0.1:17872`에서 루프백 콜백 리스너를 시작합니다. 한 번에 하나의 공급자 연결만 고정 콜백 포트를 사용할 수 있습니다. 이전 연결이 아직 대기 중이면 완료하거나 콜백 대기가 만료될 때까지 기다린 후 다시 시도하세요.

브라우저가 열리지 않으면 Atoll 로그의 인증 URL을 사용해 직접 여세요. 현재 OAuth 연결 코드는 macOS `open`을 호출하므로 Windows의 공급자 OAuth는 알려진 미검증 제한 사항입니다.

## Magnific 플랜 전파

공급자가 Premium 계정 오류와 함께 잔액 요청을 거부하면 연결된 계정에도 사용 제한이 표시될 수 있습니다. 앱은 이를 “Magnific MCP is available on premium plans only — upgrade your plan to use it.”로 표시합니다. 플랜을 변경한 후에는 공급자가 권한 변경을 반영할 때까지 기다린 다음, 같은 요청을 반복해서 시도하는 대신 잔액을 새로 고치거나 다시 연결하세요.

## 견적 및 크레딧

`$` 배지는 노드에 필요한 값이 유효해진 후에만 공급자의 견적/사전 확인 경로를 호출합니다. 작업을 제출하지 않으며 크레딧도 소모하지 않습니다. Kling의 공급자 어댑터는 MCP에서 실행 전 견적을 제공하지 않으므로 `estimate-unsupported`를 명시적으로 반환합니다. 이는 정상 동작이며 생성 실패와 다릅니다.

::: warning
공급자 크레딧이 소모됩니다. 견적이 없다고 실행이 무료라는 뜻은 아닙니다. **Run**을 사용하기 전에 공급자 잔액과 가격을 확인하세요.
:::

## 작업 시간 초과 및 재시작 복구

백그라운드 폴링 작업의 최대 시간은 30분입니다. 이 한도에 도달하면 Atoll은 로컬 추적을 시간 초과로 표시합니다. 현재 앱 경로를 통해 공급자가 취소 엔드포인트를 제공하지 않으므로, 공급자 취소 엔드포인트를 호출하지 않습니다.

작업은 워크스페이스 및 공급자 정보와 함께 저장됩니다. 워크스페이스 탭이 로드되면 캔버스는 작업 업데이트를 구독하고 로컬 작업 목록을 호출해 앱 재시작 중 또는 탭이 열리기 전에 도착한 업데이트를 조정합니다. 재시작 후 결과를 확인할 때는 먼저 워크스페이스 탭을 여세요.

## 에이전트 터미널 및 MCP

터미널은 로그인 셸을 통해 CLI를 실행하며, 세션이 시작될 때마다 워크스페이스 로컬 통합 파일을 기록합니다. 대화형 터미널에서는 CLI가 작동하지만 Atoll에서는 작동하지 않는다면 로그인 셸의 PATH를 비교하고 변경 후 세션을 다시 시작하세요.

MCP가 표시되려면 로컬 서버가 `127.0.0.1:17873`에서 수신 대기 중이어야 하고, 세션 URL에 토큰이 포함되어야 하며, 캔버스 브리지 명령을 위해 워크스페이스 탭이 열려 있어야 합니다. 에이전트 세션을 다시 시작하면 워크스페이스 등록이 새로 생성되고 연결이 다시 로드됩니다.

## 포트 참조

Atoll의 모든 개발 및 로컬 통합 리스너는 공개 인터페이스가 아닌 루프백 주소에 바인딩됩니다.

| 포트 | 소유 프로세스 | 용도 | 확인 |
| --- | --- | --- | --- |
| `9010` | Vite/Tauri 개발 서버 | 개발 전용. 구성된 개발 URL | `lsof -i :9010` |
| `17872` | Atoll 공급자 연결 흐름 | OAuth 브라우저 콜백. 연결 중에만 사용 | `lsof -i :17872` |
| `17873` | Atoll 로컬 MCP 서버 | 에이전트 세션용 캔버스 MCP HTTP 엔드포인트 | `lsof -i :17873` |

포트가 사용 중이면 무엇이 해당 포트를 소유하는지 확인한 후 중지하세요. 특정 개발 또는 연결 흐름을 소유한 프로세스만 중지하고 네트워크 보안 기능은 활성화된 상태로 유지하세요.
