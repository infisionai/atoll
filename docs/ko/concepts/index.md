# 핵심 개념

Atoll은 공급자 기반 생성 워크플로를 구성하는 로컬 우선 캔버스입니다. 가장 간단하게 이해하면 다음과 같습니다.

**캔버스 → 모델 노드 → 타입이 지정된 포트 → 실행 → 작업 → 결과 노드 → 로컬 미디어 캐시**

로컬 우선이라고 해서 오프라인으로 작동한다는 뜻은 아닙니다. Atoll은 캔버스, 작업 기록, 다운로드한 미디어를 로컬에 저장하지만, 생성·인증·모델 카탈로그를 처리할 때는 여전히 공급자 서버를 호출합니다.

## 캔버스

캔버스는 워크스페이스 안에 있는 영구 노드 그래프입니다. 모델, 에셋, 편집 노드와 노드 사이의 연결을 담으므로 워크플로를 하나의 단위로 저장하고 다시 열 수 있습니다. 워크스페이스 탭은 에이전트 명령과 작업 복구에 사용되는 범위이기도 합니다.

## 모델 노드

모델 노드는 카탈로그의 모델 하나와 해당 공급자를 나타냅니다. 필드는 모델 스키마에서 생성됩니다. 프롬프트, 미디어 입력, 필수 매개변수, 선택적 고급 매개변수가 타입이 지정되지 않은 값 모음이 아니라 폼으로 표시됩니다. 공급자 카탈로그에서 모델을 선택한 다음 실행하기 전에 노드를 채웁니다.

## 타입이 지정된 포트

포트는 `text`, `image`, `video`, `audio`, `3d` 값을 전달합니다. 연결에는 방향이 있습니다. 출력은 입력으로 연결되며, 이미지 출력과 이미지 입력처럼 동일한 타입끼리만 연결할 수 있습니다. 이미지는 텍스트 프롬프트에 연결할 수 없습니다.

## 실행

모델 노드를 실행하면 정규화된 값과 업스트림 미디어 참조가 해당 노드의 공급자에 제출됩니다. Atoll은 대기 중인 결과 노드를 만들고 반환된 작업 ID를 기록하여 캔버스가 작업을 계속 추적할 수 있게 합니다.

::: warning
공급자 크레딧이 소모됩니다. 실행하기 전에 노드와 공급자를 검토하세요.
:::

## 작업

작업은 공급자 측 생성에 대한 Atoll의 로컬 기록입니다. 제출 페이로드, 공급자, 워크스페이스, 노드, 상태, 최종 미디어 경로가 기록됩니다. 앱은 작업이 완료되거나 실패할 때까지 공급자를 폴링하며, 가능한 경우 공급자가 제안한 간격을 사용합니다. 백그라운드 추적은 30분으로 제한됩니다. 이는 추적 제한이며 공급자 측 취소가 아닙니다.

`Cancel`은 로컬 추적만 중지하고 생성 중인 결과 노드를 제거합니다. Atoll에는 공급자 취소 API가 없으므로, 제출된 공급자 작업은 취소되거나 환불되지 않으며 크레딧이 계속 소모될 수 있습니다.

## 결과 노드

모델 실행이 제출되면 결과 노드가 생성되고 대기 상태로 시작합니다. 폴링을 통해 완료된 페이로드가 확인되면 Atoll이 결과 URL을 연결하고 노드를 미디어 결과로 바꿉니다. 작업이 실패하면 대신 실패 내용이 기록됩니다.

## 로컬 미디어 캐시

공급자가 결과 URL을 반환하면 Atoll은 첫 번째 결과를 앱 데이터의 `media/` 디렉터리로 다운로드하려고 시도합니다. 다운로드에 성공하면 노드가 로컬 경로를 사용할 수 있고, 실패하면 원격 URL을 대체 경로로 유지합니다. 공급자 URL은 만료될 수 있으므로, 완료된 작업을 로컬에서 계속 사용할 수 있게 하는 것은 캐시입니다.

## 공급자

공급자는 독립된 계정, 모델 카탈로그, 크레딧 잔액을 제공하는 주체입니다. 공급자는 각각 따로 연결해야 하며, 각 공급자의 카탈로그와 잔액은 해당 공급자의 서버를 통해 가져옵니다. 그래도 포트 타입이 일치하면 공급자 간에 결과를 연결할 수 있습니다. [공급자 개요](/ko/providers/)를 참고하세요.

## 크레딧과 `$` 배지

크레딧은 선택한 공급자가 보고한 잔액을 의미하며, Atoll은 공급자별 잔액을 하나의 지갑으로 합치지 않습니다. `$` 배지는 현재 노드 값에 대한 실행 전 견적을 요청하며, 견적은 제출된 생성 작업이 아닙니다. 일부 공급자나 모델은 견적을 제공하지 않습니다. 예를 들어 Kling의 MCP에는 실행 전 견적 도구가 없으므로 배지가 표시되지 않는 것이 정상일 수 있습니다.

## 처음부터 끝까지 하나의 워크플로

캔버스에서 시작해 스키마가 폼을 만드는 모델 노드를 추가하고, 호환되는 타입의 포트를 연결합니다. 실행하면 공급자가 요청을 받고, Atoll이 작업을 기록하고 폴링하며, 결과 노드를 만들거나 업데이트하고, 반환된 미디어를 로컬 캐시로 다운로드합니다. Atoll에 인증, 카탈로그, 견적, 생성, 작업 상태가 필요한 시점에는 공급자 계정과 서버 연결이 필요합니다.

에이전트를 사용하는 동일한 흐름은 [에이전트 터미널](/ko/agents/terminal)과 [Canvas MCP 도구](/ko/reference/mcp-tools)를 참고하세요.
