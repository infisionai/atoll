# 캔버스 MCP 도구

Atoll은 로컬 스트리밍 가능한 HTTP MCP 서버를 통해 8개의 도구를 제공합니다. 서버는 `127.0.0.1:17873`에만 바인딩되며, 워크스페이스별 URL과 세션 토큰이 열려 있는 캔버스로 호출을 전달합니다.

## 연결

다음 형태의 엔드포인트를 사용합니다.

```text
http://127.0.0.1:17873/mcp/<workspace-id>?t=<session-token>
```

에이전트 터미널이 열릴 때 Atoll은 워크스페이스 `.mcp.json`에 URL을 자동으로 기록합니다. 모든 요청에 토큰이 필요합니다. 토큰은 로컬에 보관하고, 캔버스 도구를 호출하기 전에 워크스페이스 탭을 여세요. 해당 탭이 열려 있지 않으면 캔버스 변경 사항이 React 캔버스로 전달되지 않고 시간 초과됩니다.

MCP 도구 호출이 성공하면 페이로드가 `structuredContent`로 반환되고 텍스트 콘텐츠 항목에도 JSON 문자열로 반환됩니다. 도구 호출이 실패하면 텍스트 메시지와 함께 `isError: true`가 반환됩니다.

## 분류

`Read`는 로컬 캔버스 또는 공급자/작업 상태를 읽습니다. `Write`는 로컬 캔버스를 변경합니다. `Billable`은 공급자 작업을 제출하고 공급자 크레딧을 소모할 수 있는 작업을 의미합니다.

## `canvas_state`

현재 그래프를 읽습니다. 응답에는 종류, 모델 또는 참조, 값, 상태 관련 값, 모델 필드 메타데이터와 그래프 엣지가 포함된 노드가 들어 있습니다. 캔버스를 변경하기 전에 확인하세요. 붙여 넣은 `@atoll:node/<id>`는 이러한 노드 ID를 가리킵니다.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| — | — | 아니요 | 속성이 없습니다. |

응답 형태: `{ "nodes": [...], "edges": [...] }`. 모델 노드에는 `name`, `kind`, `required`, `connectable`이 포함된 `fields` 항목이 있습니다.

분류: **Read**

## `list_models`

연결된 공급자의 병합된 카탈로그를 읽습니다. 반환된 `ref`를 `canvas_add_node`의 모델 `ref`로 사용합니다.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `output_type` | 문자열 열거형: `image`, `video`, `audio`, `3d` | 아니요 | 출력 유형으로 필터링합니다. 모든 유형을 보려면 생략합니다. |

응답 형태: 각 항목에 `ref`, `name`, `output_type`, `developer`, `description`, `provider`가 포함된 `{ "models": [...] }`. 연결되지 않은 공급자는 건너뜁니다. 공급자 카탈로그를 반환할 수 없으면 도구가 마지막 카탈로그 오류를 보고합니다.

분류: **Read**

## `canvas_add_node`

캔버스에 노드를 추가합니다. `kind: "model"`인 경우 `ref`는 `list_models`에서 가져온 모델 ID여야 합니다. 에셋에는 `image` 또는 `video`를 사용하고, 편집 노드에는 편집 작업 ID를 사용합니다.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `kind` | 문자열 열거형: `model`, `asset`, `edit` | 예 | 추가할 노드 종류입니다. |
| `ref` | 문자열 | 예 | 모델 ID, 에셋 유형 또는 편집 작업 ID입니다. |
| `x` | 숫자 | 아니요 | 캔버스의 x 위치입니다. 생략하면 Atoll이 뷰포트 중앙 근처에 노드를 배치합니다. |
| `y` | 숫자 | 아니요 | 캔버스의 y 위치입니다. 생략하면 Atoll이 뷰포트 중앙 근처에 노드를 배치합니다. |
| `values` | 객체 | 아니요 | 초기 필드 값입니다. 예: `{ "prompt": "..." }` |

응답 형태: `{ "nodeId": "..." }`.

분류: **Write**

## `canvas_set_value`

기존 노드의 필드 값 하나를 설정합니다. 먼저 `canvas_state`를 사용해 모델의 필드 이름을 확인하세요.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `nodeId` | 문자열 | 예 | 대상 노드 ID입니다. |
| `name` | 문자열 | 예 | `prompt` 또는 `aspect_ratio`와 같은 필드 이름입니다. |
| `value` | 모든 JSON 값 | 예 | 저장할 값입니다. 스키마에서 이 유형을 일부러 지정하지 않았습니다. |

응답 형태: `{ "ok": true }`.

분류: **Write**

## `canvas_connect`

노드의 출력을 다른 노드의 입력 포트에 연결합니다. 캔버스는 출력에서 입력으로 향하는 방향이 올바른지, 포트 유형이 정확히 일치하는지 확인합니다.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `fromNode` | 문자열 | 예 | 소스 노드 ID입니다. 해당 노드의 출력 포트를 사용합니다. |
| `toNode` | 문자열 | 예 | 대상 노드 ID입니다. |
| `toPort` | 문자열 | 예 | `canvas_state`에 있는 대상 입력 필드 이름입니다. |

응답 형태: `{ "ok": true }`.

분류: **Write**

## `canvas_disconnect`

노드 출력과 입력 포트 사이의 연결을 제거합니다.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `fromNode` | 문자열 | 예 | 소스 노드 ID입니다. |
| `toNode` | 문자열 | 예 | 대상 노드 ID입니다. |
| `toPort` | 문자열 | 예 | 대상 입력 포트 이름입니다. |

응답 형태: `{ "ok": true }`.

분류: **Write**

## `canvas_run`

생성을 위해 모델 노드를 실행합니다. Atoll은 보류 중인 결과 노드를 자동으로 만들고 공급자 작업 ID를 반환합니다. 완료 상태를 확인하려면 `job_wait`를 사용하세요.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `nodeId` | 문자열 | 예 | 실행할 모델 노드입니다. |

응답 형태: `{ "jobIds": ["..."] }`.

::: danger
`canvas_run`은 과금 대상입니다. 공급자 크레딧이 소모됩니다. 사용자가 생성을 명시적으로 요청한 후에만 호출하세요.
:::

분류: **Write · Billable**

## `job_wait`

현재 워크스페이스에 속한 생성 작업을 기다립니다. Atoll의 폴링 작업자가 공급자를 확인하는 동안 도구는 로컬에서 추적하는 상태를 감시합니다.

입력 스키마:

| 이름 | 유형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `jobId` | 문자열 | 예 | `canvas_run`에서 반환된 작업 ID입니다. |
| `timeoutSeconds` | 숫자 | 아니요 | 최대 대기 시간입니다. 기본값은 `180`초이며 5~600초로 제한됩니다. |

응답 형태:

- 완료: `{ "status": "done", "urls": [...], "localPath": "..." }` (`localPath`는 없을 수 있습니다.)
- 실패: `{ "status": "failed", "message": "..." }`.
- 요청한 대기 한도까지 계속 실행 중: `{ "status": "running", "note": "Still in progress — call job_wait again" }`.

분류: **Read**
